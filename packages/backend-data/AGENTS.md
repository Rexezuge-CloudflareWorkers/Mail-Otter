# Mail-Otter — Backend Data (D1/DAO Layer)

Scope: `packages/backend-data/**`. Parent index: `../../AGENTS.md`.

All D1 access via DAOs: `ConnectedApplicationDAO` (+ `ConnectedApplicationFlags.ts` flag helpers; metadata shaping extracted to `ConnectedApplicationMetadataMapper.ts` (`assembleMetadata` pure + `migrateLegacyExcludeRules` via `MetadataConfigWriter` seam); incl. `content_language` provider-config row + `updateContentLanguageForUser`), `ApplicationContextDAO` (facade over `ContextAuditLogDAO` + `ContextDeletionRunDAO`; document queries in `ApplicationContextDocumentQueries.ts`), `UserDAO` (`preferred_language` + `updatePreferredLanguage`; plus the 0028 identity surface `createUser`/`getById`/`getByCurrentEmail`/`getRowByEmail`/`setCurrentEmail` and the statics `newId()`/`newAnchor()`), `UserEmailDAO` (the address registry; `register` refuses a _verified_ row and re-points a revoked one), `userScope.ts` (`userScopeSql(scope, alias?)` — the one ownership predicate: `user_id = ? OR (user_id IS NULL AND user_email = ?)`, plus `scopeForAnchor` for the row-carried paths and `userScopeUpsertSql` for dual-writes), `ProcessedMessageDAO`, `OAuth2AuthorizationSessionDAO`, `ProviderSubscriptionDAO`, `AiDailyUsageDAO`, `EmailActionDAO` (queries in `EmailActionQueries.ts`), `OAuth2AccessTokenCacheDAO`, `OAuth2AccessTokenRefreshStatusDAO`, `ApplicationIntegrationDAO`, `BackgroundTaskRunDAO`, `IntegrationDeliveryLogDAO`, `SyncedCalendarEventDAO`, `ActivityDAO`; `BaseDAO` generic helpers `findById`/`deleteOlderThan` (static) + instance variants `findRowById`/`deleteRowsOlderThanRows`/`encodeCursor`/`decodeCursor` (additive; new DAOs use instance variants); KV token cache; utils `D1SessionUtil`, `CursorUtil`, `D1ErrorClassifier`, `D1Utils`, `RepositoryHelper` (`pruneInBatches`, `computeUnixCutoffSeconds`, `computeDateCutoffIso`, `DEFAULT_PRUNE_BATCH_SIZE`); `CryptoService` (AES-GCM); `BaseDAO.withRetry`; constants `ProviderConfigKeys.ts` (single source for provider-config row keys). Per-app settings without columns (time zone, content language, features, filters, rules) → provider-config key/value rows.

**Identity keys (migration 0028):** `users.email` is a **frozen anchor** — the PRIMARY KEY, the target of every legacy `FOREIGN KEY (user_email) REFERENCES users(email)`, and the input to the Vectorize namespace. Never `UPDATE` it. `users.id` is the stable account key; `users.current_email` the mutable sign-in address; `user_emails` the address registry. `user_id` is backfilled on `connected_applications`, `application_context_documents`, `application_context_deletion_runs`, `email_summary_actions` and `context_audit_logs`. Any new user-keyed table gets `user_id TEXT REFERENCES users(id)` and a `userScopeSql` predicate — a bare `user_email = ?` will 404 the owner after an address change.

Key provider-config rows: `calendar_time_zone`, `content_language`, `attachment_vision_enabled`, `sender_domain_filters`, `google_drive_page_token`, `onedrive_delta_link`, `digest_enabled`, `digest_send_time`, `digest_sections`, `digest_last_sent_at`.
